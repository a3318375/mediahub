# STRM 生成与手动刮削

在「全局设置 → STRM 生成」填写：

- **115 来源目录**：默认填写媒体整理中的“已整理目录”，仍可选择其他目录。
- **STRM 输出目录**：固定输出，无需配置。Docker 为 `/strm`（挂载到宿主机持久化），当前 Windows 开发环境为 `D:\tmp\res\strm`。
- **播放服务地址**：后台自动获取本机局域网 IP 和后端监听端口，无需填写。手动与定时生成使用相同的地址识别逻辑。
- **定时生成 Cron**：5 段格式，按北京时间执行；留空仅支持手动生成。

保存不会立即执行。到「媒体处理 → STRM 生成」点击生成；只有配置完整后按钮才可用。定时和手动使用同一个生成方法，按网盘目录结构生成本地 `.strm`，不下载视频。

STRM 内容是带单文件签名的 MediaHub 播放地址。播放时后端获取 115 当前有效地址并转发视频，支持 GET、HEAD 和 Range。视频流量经过 MediaHub；115 Cookie 不会写入 STRM。此版本不提供客户端直连 CDN 的 302 模式。

在「全局设置 → 元数据刮削」填写本地刮削目录，可直接使用 STRM 输出目录。到刮削 Tab 手动触发，当前没有定时选项。它会扫描视频与 STRM，在相邻位置生成 NFO、海报以及来源提供的背景图；电视剧还会生成 `tvshow.nfo`。

刮削优先使用已有 TMDB / Bangumi 作品与季集关联。未关联文件通过 TMDB 精确匹配，需要已有 TMDB Key；不明确的匹配保留为未完成。番剧支持 Bangumi 的分部集号与绝对集号，无法唯一对应时报告错误。

已有文件不覆盖、不删除；内容相同则跳过，内容冲突时记录原因。NFO 已写入但图片获取失败、作品无法识别或集数不明确，都计入未完全刮削，可查看原因后重试。每次任务最多扫描 10000 个文件，扫描或网络失败会保留已经完成的结果。

任务状态和最近失败原因显示在各自 Tab；统计统一记录到最近作品表。来源目录未设置时不会生成 STRM；Cron 留空不会定时触发。刮削目录未配置时不会执行刮削。
