# 媒体处理、STRM 与刮削

「媒体处理」的下载、整理、STRM 和刮削共用最近作品记录。「立即下载」处理订阅候选和待处理队列，「立即整理」按已保存的目录执行一轮整理。手动触发沿用各自的后台任务和规则，不修改定时设置。

最近记录从 `GET /api/v1/organize/items` 读取。资源按确认的媒体文件去重，字幕不计入资源数。最近 14 天最多保留 100 条，即使超过 14 天也保留最新 10 条，执行中的作品不参与清理。该规则只清理统计记录。涉及番剧集数映射时，参见[动漫集数偏移链路](web/动漫集数偏移链路.md)。

## STRM 生成

在「全局设置 → STRM 生成」填写：

- **115 来源目录**：留空时沿用媒体整理中的“已整理目录”，也可选择其他目录。
- **STRM 输出目录**：固定输出，无需配置。Docker 为 `/strm`（挂载到宿主机持久化），当前 Windows 开发环境为 `D:\tmp\res\strm`。
- **播放服务地址**：应是播放器能访问的 MediaHub 地址。后端优先使用保存的地址，未保存时尝试使用本机局域网 IP 和监听端口。UIArc 手动生成时沿用已保存的地址。
- **定时生成 Cron**：5 段格式，按北京时间执行；留空仅支持手动生成。

保存不会立即执行。到「媒体处理 → STRM 生成」可手动触发，后端会检查是否有可用的来源目录和播放地址。定时和手动使用同一个生成方法，按网盘目录结构生成本地 `.strm`，不下载视频。

## 播放和排查

STRM 内容是带单文件签名的 MediaHub 地址。GET 和 HEAD 在签名及文件记录校验通过后返回 HTTP 302，由播放器直接访问 115 HTTPS 直链。后端按文件版本和播放器 User-Agent 短时缓存解析结果。115 Cookie 不会写入 STRM 或发给播放器。

播放器所在网络须能访问 115，并能在跳转后保持 User-Agent 和 Range 请求。排查时用相同的 User-Agent 先检查是否返回 302，再从播放器所在网络跟随跳转，确认是否收到 200 或 206。反馈问题时请遮挡签名和完整的重定向地址。

## 手动刮削

在「全局设置 → 元数据刮削」填写本地刮削目录，可直接使用 STRM 输出目录。到刮削 Tab 手动触发，当前没有定时选项。它会扫描视频与 STRM，在相邻位置生成 NFO、海报以及来源提供的背景图；电视剧还会生成 `tvshow.nfo`。

刮削优先使用已有 TMDB / Bangumi 作品与季集关联。未关联文件通过 TMDB 精确匹配，需要已有 TMDB Key；不明确的匹配保留为未完成。番剧支持 Bangumi 的分部集号与绝对集号，无法唯一对应时报告错误。

已有文件不覆盖、不删除；内容相同则跳过，内容冲突时记录原因。NFO 已写入但图片获取失败、作品无法识别或集数不明确，都计入未完全刮削，可查看原因后重试。每次任务最多扫描 10000 个文件，扫描或网络失败会保留已经完成的结果。

任务状态和最近失败原因显示在各自 Tab，结果计入最近作品统计。
