# 动漫集数偏移链路

以季数 1、来源偏移 -40 为例：

| 原始资源集号 | 保存的原始集号 | 保存的目标集号 | 整理 / STRM / NFO 集号 |
| --- | --- | --- | --- |
| 41 | 41 | 1 | S01E01 |
| 49 | 49 | 9 | S01E09 |
| 后续更新 50 | 50 | 10 | S01E10 |

原始文件示例：`[UHA-WINGS][Bleach Sennen Kessen-hen][41][x264 1080p][CHS].mp4`。

## 处理约定

1. RSS 从原标题解析集号，保存 `originalEpisode`，使用该来源的偏移计算 `episode`。每次刷新都从原标题重新计算，不在上次结果上叠加；备用 RSS 使用自己的偏移。
2. 下载候选和下载引用保存 `OriginalEpisodes`、`Episodes`、`Offset`、季数、作品身份及规则版本。下载文件保持上游原名。相同资源重复刷新不创建重复候选，也不静默重写已经执行的任务快照。
3. 整理单文件使用已确认的任务映射。合集不将任务中的单集信息复制给所有文件：清除任务级目标和原始集号，再按每个文件解析、应用偏移。支持单个纯数字方括号集号（含 v2），多个数字括号、合集范围、特别篇与无效目标集号需要明确映射。
4. 完成的整理 action 保存逐文件映射。STRM 查询优先级为显式文件绑定、已完成整理 action、下载任务；优先读取整理结果，避免退回合集的任务级信息。校验文件大小与 SHA1 的既有行为保留。
5. STRM 沿用云端整理后的目录和名称，内容仍按稳定文件 ID 指向播放接口。元数据解析错误会记录失败，不继续写入错误季集的输出。重复生成跳过已有 STRM，不再次应用偏移。
6. NFO 使用目标季集号；Bangumi 分集查询保留原始集号（该提供者支持绝对 sort / 分部 ep）；TMDB 使用目标季集号。不会为了命中元数据而另行推算偏移。
7. 后续 RSS 50 按同样的 -40 得到 10；刷新、重启和重复整理不会把 9 再减 40。

## 边界

- 文件名本身不能唯一证明作品、季数或偏移。没有完成下载记录或显式绑定的历史文件仍会报告未就绪，不按近似标题猜订阅。
- 当前订阅 PATCH 只支持启停，不支持编辑既有偏移。若后续增加编辑功能，需要独立定义待下载候选重新计算、未整理任务重新预览、已整理文件与 STRM/NFO 的显式迁移，不能直接对历史结果叠加新偏移。
- 本地模拟通过不代表 NAS 运行中的版本已更新，也不能替代对 NAS 具体跳过原因的核验。

## 回归验证

`go test ./internal/mediaoutput -run TestBleachOffsetFromRSSViaDownloadAndOrganizeToOutput -count=1`

用 41、49、50 覆盖 RSS 重复解析、任务 JSON 持久化边界、单文件和合集、真实整理预览目标名、重复读取映射、NFO 集号，以及实际 STRM 文件生成和重复生成。云端网关及仓库使用内存模拟，不提交下载、不连接 115、不读写项目数据库。STRM 测试输出使用测试临时目录。
