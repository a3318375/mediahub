# 媒体处理与最近记录

四个 Tab 共用 `media_processing_records`。这是一张 SQLite 普通表，按 115 账号和作品标识区分记录，并按最近活动时间建立索引。页面读取表中已保存的统计，不在每次刷新时重算下载与整理历史。

表中保存作品类型、标题、资源数、已整理数、未整理数、STRM 生成数、已刮削数、未完全刮削数及活动时间。资源数按已确认的媒体文件 ID 去重，字幕不计入资源数。STRM 显示已生成和未生成数量；刮削显示完整与未完全刮削数量，未开始的文件也计入未完全刮削。

订阅新增、下载任务变化、整理计划变化会通知统一统计工作器；工作器合并短时间内的通知并更新此表。下载与整理调度结束时也会通知统计工作器。启动时同步已有真实数据，每分钟补查一次，确保记录保留策略及时执行。

最近记录保留 14 天内最多 100 条；旧记录保留最近 10 条作为历史视图。执行中的作品不参与淘汰，因此任务很多时可暂时超过 100 条。清理只针对此表，不删除订阅、下载任务、整理计划、配置或网盘文件。

「立即整理」向现有整理工作器发送唤醒信号，用全局设置的目录与规则手动执行一次，不修改 Cron 或启用状态；文件处理与定时执行共用同一个调度入口。「立即下载」唤醒现有下载工作器，处理订阅候选和待处理队列，沿用已有退避与凭据检查。

STRM 定时和手动入口共用生成工作器；刮削目前只支持手动执行。两者在状态改变后通知统一统计工作器，按实际输出结果更新数量。配置保存在 `media_output_jobs`，文件映射保存在 `media_output_files`；读取设置不会自动创建默认配置。

配置与使用方式见 [STRM 与刮削](media-output.md)。

## 代码结构与边界

- `hero/src/pages/processing/`：四个处理 Tab、最近记录、任务状态和手动触发；不编辑目录规则，也不直接请求网盘或元数据网站。
- `hero/src/pages/settings/`：全局配置，以及整理预览、异常处理。`pages/downloads/Downloads.tsx` 仍用于下载明细和下载弹窗，不是废弃页面。
- `hero/src/lib/*-api.ts`：真实 HTTP 接口、请求参数和类型。旧整理页面已移除；规则、绑定等接口仍供兼容流程和联调脚本使用。
- `api/internal/httpapi/`：认证、参数校验、HTTP 响应；`output_metadata.go` 适配 TMDB/Bangumi，向工作器提供统一元数据，`media_output.go` 提供任务和签名播放入口。
- `api/internal/download/`、`organize/`：已有下载与整理工作器。手动操作只唤醒工作器，与定时执行共用业务逻辑。
- `api/internal/mediaoutput/`：`service.go` 管理队列、定时和状态；`generate.go` 负责网盘遍历及 STRM；`scrape.go` 负责本地刮削；`files.go` 提供安全写入和 NFO 等文件能力。不依赖 HTTP 或 SQLite。
- `api/internal/store/`：SQLite 持久化、默认整理来源和统一统计投影。最近记录表是查询视图，不替代订阅、下载、整理和输出文件记录；页面读取不触发全历史重算。首次手动执行也必须保存任务状态。

`web/` 是仍保留的 shadcn 前端，`hero/` 是当前使用的 Hero 前端；本次不改动旧前端的业务入口。最近记录接口暂沿用 `/api/v1/organize/items`，四个 Tab 共用，避免为界面重命名破坏现有调用。

STRM 输出路径与播放地址由后端运行环境决定；115 来源可以配置，留空时读取全局整理目标。保存设置不执行任务，读取默认值不写入配置。刮削目前只补充基础 NFO 和图片，不承担媒体服务器的完整元数据管理。
