# FRAME 媒体中心 Web

> **已放弃维护**：此目录为历史版本，不再更新。当前前端为 [`../hero/`](../hero/)，说明见 [DEPRECATED.md](DEPRECATED.md)。以下内容仅供历史参考。

影视与动漫检索、订阅和网盘整理的一体化操作界面。项目目标是整合 ani-rss、tgtodriver 和 PanSou，让用户从发现作品、查找资源、订阅更新，到下载或转存至 115 网盘、整理媒体文件，在同一套界面中完成操作。

这是一条逐步接入的业务链路；当前界面包含真实 API、开发演示数据和待实现入口，不能把页面存在或配置保存成功视为完整业务已接入。

## 产品目标与职责

- 元数据探索：识别影视和动漫作品，保留来源、媒体类型和原生 ID，供检索与订阅使用。
- PanSou：提供资源检索、来源选择和分享链接检测；资源命中不代表已经下载。
- ani-rss：作为动漫订阅与更新能力的集成目标，接入方式及任务契约待确定。
- tgtodriver：作为下载、转存至 115 与文件处理链路的集成目标，具体能力和职责以后续对接验收为准。
- 媒体中心：统一作品身份、配置、订阅和任务状态，让下载与整理进度可查询、失败可重试。

前端负责展示、用户输入和任务反馈；后端负责凭证、上游适配、调度、幂等与文件操作。前端不直接持有上游服务密钥，不负责执行后台下载或整理任务。保持现有页面设计，以渐进接入为主。

## 本地开发

技术栈：React、TypeScript、Vite、Tailwind CSS 4、shadcn/ui。先执行 `pnpm install`。

界面演示：

```powershell
pnpm dev
```

开发默认启用 MSW，演示账号 `admin` / `123456`。演示并非完全离线：部分媒体请求与 TMDB 设置会穿透到后端，资源接口没有 mock。

连接真实后端，并保留尚未接入的演示接口：

```powershell
$env:VITE_BACKEND_AUTH = 'true'
$env:VITE_API_PROXY_TARGET = 'http://127.0.0.1:18080'
pnpm dev
```

完全关闭 mock：

```powershell
$env:VITE_ENABLE_MOCKS = 'false'
pnpm dev
```

未实现的接口此时会失败，不再返回演示数据。真实后端首次启动需要初始化管理员；上游凭证在全局设置中配置。生产构建不启用 MSW，需要同源 `/api` 反向代理，并将前端页面路径回退到 `index.html`。Vite 开发代理不随 dist 部署。

## 目录与契约

- `src/layouts/media-shell`：侧栏、顶栏、导航、用户面板。
- `src/components`：业务页面；`src/components/ui`：公共 UI 组件。
- `src/lib/media-contract.ts`：正式媒体契约，身份包含 provider、mediaType、providerId。
- `src/lib/*-api.ts`：认证、媒体、设置、日志等 API 封装。
- `src/lib/anime-api.ts`：正式订阅契约、来源与订阅 API；`src/components/add-anime-subscription.tsx`：添加流程。
- `src/lib/resource-search.ts`：搜索策略、历史和链接校验；资源 HTTP 调用目前位于页面内。
- `src/mocks`：开发演示接口与数据；正式业务类型应逐步脱离此目录。
- `tests`：资源策略及媒体展示逻辑测试。
- `doc`：接入进度和检查记录。

后续接入优先明确订阅到下载再到整理的任务契约、重复处理规则与失败语义，再接到现有页面；涉及交互或设计调整先由维护者决定。

## 动漫订阅首版

进入动漫订阅，点击添加订阅；可浏览 Mikan 的季度、番剧、字幕组与发布样本，或输入 Mikan/其他 RSS 2.0。其他来源需提供 Bangumi ID。服务端解析作品信息后，可编辑标题、季、偏移、总集数、更新星期、匹配/排除正则与最多 5 个备用 RSS；预览显示每条原标题、识别集数、排除原因和预计文件名。

匹配为全部规则命中，排除为任意规则命中。正则使用 Go RE2 语法，不支持回溯引用与前后查找。当前集数识别支持 SxxExx、中文“第 N 集/话”和常见方括号/连字符编号；不识别的条目明确拒绝，不推算合集集数。备用来源独立偏移，同集主来源优先。

创建和启用状态保存到 SQLite，同一 Bangumi ID+季不允许重复，不会自动替换。保存/启用不会提交下载；下载历史、115 下载执行和整理尚未接入。未知更新时间和下载进度保留缺失状态。AniBT/AnimeGarden 浏览、批量添加、自动偏移和编辑既有订阅规则留待后续。

Mikan 列表缓存 10 分钟、字幕组 2 分钟、Bangumi 元数据 30 分钟；来源页可强制刷新，RSS 预览每次读取上游。标准来源使用当前环境代理；自定义 RSS 直接连接经过校验的公网 IP。所有接口使用 `/api/v1` 鉴权，不再走订阅演示接口。

2026-10-13 验证：前端类型检查、lint、构建及原有 13 项测试通过；后端全部 test/vet/build 通过，新增覆盖规则/偏移/去重、缓存、鉴权、暂停、重复创建和重启持久化。真实 Mikan/Bangumi 草稿与预览请求已验证，尚未完成浏览器交互验收。

字幕组选择后先进入版本匹配步骤：从实际发布标题提取分辨率、字幕语言、封装与编码组合，去重后提供候选，另提供全部选项；选择写入 match，全部不添加匹配条件，已有排除规则仍生效。候选组合不固定为简/繁。

## 订阅更新（2026-10-14）

添加后尝试更新一次；卡片右下角可单独刷新，失败显示原因并保留上次资源结果。页头“刷新”只重新读取数据库列表。未配置 115 也允许添加/手动更新 RSS，不会提交下载。

北京时间每天 04:00 自动刷新当天及前一天启用且未完结的订阅；Bangumi 约 12 小时同步评分/元数据和缺失总集数。115 Cookie 未配置或不可解密时，自动 RSS/Bangumi 任务停用，不建立周期任务或发上游请求；在全局设置中保存/清除 115 配置后立即重新判断。

完成条件为累计有效整数单集覆盖 1..总集数；缺集、未知总集数、特别集不会误判完成。完成后不再自动或手动抓取。“资源已更新”与下载/整理进度分开，当前不执行 115 下载。已有非空标题、总集数、季、偏移、星期及规则不被 Bangumi 同步覆盖。

完整后续工作、源码证据及凌晨发布边界见 [ani-rss 调研待办](../docs/web/ani-rss调研待办.md)。

## 已保存凭证显示

基础配置的 TMDB/Emby API Key、115 Cookie，以及机器人 Token，默认显示前 4 位与后 4 位，中间遮挡；短凭证减少可见字符。点击“显示全文”直接读取并展开，再点“隐藏”恢复脱敏，不需要再次验证密码。115 Cookie 支持多行全文显示。

点击“修改”输入替换值；取消修改或留空保留原凭证。脱敏文本和展开查看的已保存值不会当作新值提交，保存后恢复脱敏。数据库仍使用现有加密存储。基础配置页初始化包含 tmdb/emby/115，重新打开页面可显示已保存状态。
